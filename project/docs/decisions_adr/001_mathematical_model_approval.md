## Контекст

Этап математического моделирования (Stage 2) завершён. Задача T2.1 зафиксировала канон формул в `docs/ssot/02_math_model_ssot.md` (draft v0.1.0). Задача T2.2 независимо воспроизвела оракулы §14 и каталог предохранителей G-01…G-21 чистыми функциями: 48/48 проверок PASS, seed `42`, `np.seterr(divide="raise")`. Контрольный повторный прогон 2026-09-04 дал тот же вердикт.

Без утверждения L1 документ остаётся `draft`: любой следующий агент мог бы «уточнить» формулу под удобство реализации, и защищаемая модель перестала бы быть единственной. Инженерная спецификация при этом содержит сжатые и частично конкурирующие записи (`CONF-05`): сумма \(CF\) без коэффициента перевода энергии; экспоненциальный soft-SLA; слагаемое стоимости \(S_K\); псевдокод, возвращающий `Score=0` при нарушении дедлайна; balanced-режим с \(w_C=0{,}5\) рядом с YAML \((0{,}6,\,0{,}2,\,0{,}2)\). Эти расхождения нельзя оставлять на усмотрение разработчика.

Решение нельзя отложить: Stage 3 (архитектура) и реализация `pkg/energy`, `pkg/carbon`, scoring обязаны ссылаться на один замкнутый набор уравнений.

## Решение

1. **Утверждается** математическая модель [`docs/ssot/02_math_model_ssot.md`](../ssot/02_math_model_ssot.md) версии **1.0.0**, статус **`accepted` (LOCKED)**. Содержание формул тождественно draft v0.1.0; изменены статус, шапка и закрывающий §18.

2. **Единственный нормативный источник формул** для кода, экспериментов и текста диплома — указанный SSOT. Формулы (2.1)–(2.23), предохранители G-01…G-21, нормативные параметры §13 и эталоны §14 **заморожены**.

3. **Запрет на правку без нового ADR.** Ни один агент разработки (L2/L3) не вправе изменять утверждённые формулы. Изменение канона = новый ADR со статусом `accepted` + правка SSOT уровнем L1, затем код (`SSOT-01`, `SSOT-04`, `VER-18`). Прямая правка «под реализацию» запрещена.

4. **Приоритет документов.** В `CONF-03` (`governance.md` v1.1.0) после ADR вставляется `02_math_model_ssot.md` как канон формул, выше `requirements.md` и `architecture.md`.

5. **Уточнения относительно инженерной спецификации** (`CONF-05`; спецификация не переписывается):

   | Тема | Спецификация (входной канон) | Утверждённый канон |
   | --- | --- | --- |
   | Размерность \(CF\) | сжатая \(\sum P_i\Delta t_i CI_i\) (§12, `SCOPE-IN-05`) | обязателен \(\eta\) (2.1); runtime — (2.10s) |
   | Объект scoring | не разделён явно с cluster KPI | IDLE-NONE: \(\widehat{CF}(p,n)\) без idle; cluster \(CF\) — с idle |
   | \(S_C,S_R,S_P\) | §18 на \([0,1]\); глава 1 (1.9) на \([0,100]\) | частные скоринги на \([0,1]\), затем \(\times 100\) в (2.19); (1.9) \(=100\cdot S_C\) |
   | \(S_P\) / \(S_T\) | экспонента \(e^{-k(\cdot)}\) при нарушении цели (§21) | hard-отсечение (2.13) в `PreScore`; soft — линейный slack (2.18); \(k\) не калибруется |
   | SLA в псевдокоде | `return 0` (§26) | `Score=0` **не** hard-cut; `fwk.Error` / `SLA precondition failed` |
   | \(S_K\), \(w_K\) | входят в §22 | \(w_K=0\), слагаемое отсутствует (`SCOPE-EDGE-07`) |
   | Default-веса | prose Balanced \(w_C=0{,}5\); YAML \(0{,}6/0{,}2/0{,}2\) | \((w_C,w_R,w_P)=(0{,}6,\,0{,}2,\,0{,}2)\) |
   | Стратегия B | «carbon-only» без операционализации | (2.23) по текущей \(CI\), не \(w_C=1\) на (2.10) |
   | \(u\notin[0,1]\) | подразумевается Filter | явный \(\operatorname{clip}\) (2.2)–(2.3) |
   | \(\hat T(p,n)\) | может зависеть от узла в псевдокоде | канон (2.12): \(\hat T=T_{\mathrm{class}(p)}\) |
   | \(\gamma\neq 1\) | не запрещён в анализе | runtime \(\gamma=1\); иное — только ADR |

6. **Не входит в канон и не открывает права на правку формул** (замечания T2.2, defer):

   - относительный порог вместо абсолютного \(\varepsilon_{CF}=10^{-6}\,\mathrm{gCO_2e}\);
   - экспоненциальный \(S_P\);
   - node-dependent runtime;
   - freeze Python 3.11 в `analysis/requirements.txt` (toolchain анализа, не модель).

## Обоснование

Защищается алгоритм, а не программа: при расхождении кода и модели права модель (ADR-000, `SSOT-04`). Утверждение после независимой численной проверки, а не одновременно с T2.1, исключает самоподтверждение автора формул.

Коэффициент \(\eta\) обязателен, потому что произведение ватт, времени и `gCO2e/kWh` без перевода в kWh не имеет размерности gCO2e и завышает результат в \(10^{3}\) раз (часовая форма) — это закрывает QG1-R01. Политика IDLE-NONE следует из инварианта всегда включённых узлов: idle не ранжирует кандидатов и не должен дважды входить в pod-оценку (QG1-R02). Линейный slack \(S_P\) сохраняет hard-слой `SCOPE-IN-08` без свободного \(k\). Нейтральная ветвь \(S_C=1/2\) при вырождении разброса закрывает `GO-14` и не выдаёт ложный «идеальный углерод» (\(S_C=1\)). Стратегия B как min текущей \(CI\) делает экспериментальное сравнение B/C идентифицируемым на волатильном ряде (QG1-R06; T2.2: 4 горизонта расхождения).

Default-веса взяты из YAML-примера спецификации §23, согласованного с таблицей режимов SSOT, а не из конкурирующей прозаической строки \(w_C=0{,}5\).

## Последствия

### Положительные

- Единственный замкнутый набор уравнений для `pkg/energy`, `pkg/carbon` и scoring.
- Размерности W, s/h, kWh, `gCO2e/kWh`, gCO2e согласованы; эталон \(3{,}6\,\mathrm{gCO_2e}\) обязателен в unit-тестах (`DOD-TEST-03`).
- Краевые случаи G-01…G-21 не порождают \(0/0\), `NaN` и панику (`GO-06`, `GO-14`).
- Стратегии B и C операционально различны.
- Горячий путь `Score` остаётся \(O(1)\) (`SCOPE-OUT-17`).
- Глава 2 диплома трассируется к заблокированному SSOT без параллельной «авторской» записи формул.

### Отрицательные / компромиссы

- Скачок \(S_C\) на пороге \(\varepsilon_{CF}\) (с \((1,0)\) на \((1/2,1/2)\)) — намеренный численный предохранитель, не липшицева непрерывность; обязан быть прокомментирован в `pkg/scheduler`.
- При (2.12) величина \(S_P\) одинакова для всех узлов \(\mathcal{N}_{\mathrm{SLA}}\) и не меняет \(\operatorname{argmax}\); различение по производительности без node-dependent runtime было бы фиктивным.
- Итоговый контракт Scheduler Framework — 101 целое значение \([0,100]\); близкие кандидаты могут получить ничью.
- Относительная «практическая неразличимость» зон не моделируется абсолютным \(\varepsilon_{CF}\); введение относительного порога — отдельный ADR.
- Процедура изменения формул замедляет разработчиков: обнаруженный пробел оформляется Change Request, а не «быстрой правкой».

### Влияние на SSOT и код

- **Каталоги / пакеты:** `pkg/energy` реализует (2.2)–(2.6a); `pkg/carbon` — (2.7)–(2.11) и (2.10s); scoring в `pkg/scheduler` — (2.13)–(2.23) и G-*; горячий `Score` — lookup.
- **CRD / API:** не применимо; параметры модели — ConfigMap / конфигурация сценария (`GO-12`, `REPRO-06`).
- **Эксперименты / метрики:** оракулы §14 — обязательные табличные тесты; sweep весов обязан пересекать линию \(w_C=0{,}7\,w_R\) на конфликтном сценарии; cluster KPI считается по (2.9a), а не по сумме \(\widehat{CF}\).
- **Документы:** SSOT v1.0.0 LOCKED; `governance.md` v1.1.0 (`CONF-03`); глава 2; Quality Gate 2.

## Альтернативы

| Вариант | Почему отклонён |
| --- | --- |
| Оставить SSOT в статусе `draft` до появления кода | Код начал бы определять модель; нарушает `SSOT-04` и цель Stage 2 Lock |
| Перенести сжатую сумму спецификации §12 в код «как есть» | Размерностно не замкнута; оракул 14.2 был бы завышен в \(10^{3}\) раз |
| IDLE-SHARE: доля \(P_{\mathrm{idle}}\) новому поду | Двойной счёт idle; при однородных узлах не ранжирует, при разнородных искажает маржу |
| Экспоненциальный \(S_P\) из §21 | Свободный \(k\) без калибровки; soft-слой дублирует hard-cut |
| `Score=0` как отсечение SLA | Фреймворк всё ещё может выбрать узел; нарушает `SCOPE-IN-08` |
| \(S_C=1\) при \(CF_{\max}=CF_{\min}\) | Нет \(0/0\), но ложный «идеальный углерод»; канон — \(1/2\) |
| Стратегия B = \(w_C=1\) на \(\widehat{CF}\) | B и C совпали бы на однородных \(P\) и почти постоянном \(CI\) |
| \(\gamma\neq 1\) или node-dependent \(\hat T\) в runtime | Требуют новой калибровки и отдельного ADR (`SCOPE-IN-04`, `SCOPE-IN-06`) |
| Включить \(S_K\) в (2.19) | `SCOPE-EDGE-07`; cost не является предметом зачётного сравнения |
| Относительный \(\varepsilon_{CF}\) сразу в канон | Не блокирует корректность; меняет семантику вырождения без необходимости |

## Проверка

1. **Статус SSOT.** Шапка `02_math_model_ssot.md`: версия `1.0.0`, статус `accepted (LOCKED)`, баннер ADR-001.
2. **Формулы.** Любая вычислительная функция в `pkg/energy`, `pkg/carbon`, scoring обязана ссылаться на номер (2.x) и совпадать с эталоном §14 (`DOD-TEST-03`). Расхождение — дефект кода, не документа.
3. **Предохранители.** Табличные тесты G-01…G-21 (`DOD-TEST-04`); деление на ноль и `panic` запрещены.
4. **Стратегия B.** Integration/unit: на волатильном профиле \(10\to 800\to 10\) при \(\hat T=1{,}5\,\mathrm{h}\) ranking B и C различаются.
5. **Сложность.** В `Score` нет суммирования по \(K\); проверка ревью и микробенчмарком.
6. **Процесс.** Diff в `docs/ssot/02_math_model_ssot.md` после этой даты без нового ADR — нарушение, подлежит откату (`SSOT-01`).
7. **Глава 2.** Каждая нумерованная формула главы совпадает с одноимённой формулой SSOT (контрольная таблица Quality Gate 2).
8. **Повтор валидации.** `python analysis/scripts/validate_math_model.py --output-dir docs/research/figures/math_model_validation --seed 42` → `verdict=PASS checks=48 failed=0`.
