## Нумерация SSOT vs задание

В LOCKED SSOT **T5.2** = автомат PreScore, **T5.3** = Worker. Настоящий таск по постановке пользователя — **extension points** (после Worker T5.2). Следующий агент — **математические вычисления (T5.4)**. SSOT не менялся.

Расхождение формулировки задания с каноном (политика отказов §6): SLA, \(P(u)\), \(\widehat{CF}\) и RawScore считаются в **PreScore**, не в `Score`. `Score` — \(O(1)\) lookup. Min-max \(S_C\) (включая \(CF_{\max}=CF_{\min}\)) — в PreScore (G-04), не в `NormalizeScore`. Hard SLA — `PreScore` **Error**, не `Score=0`. Реализация следует SSOT.

## CycleState

Ключ: `carbon-aware.io/CarbonAware` (`API-STATE-01`).

Обёртка `cycleStateData` в `pkg/scheduler/cycle_state.go` удовлетворяет `fwk.StateData` (`Clone()` = тот же указатель). Payload — неизменяемый `v1alpha1.CarbonCycleState`:

| Поле | Назначение |
| --- | --- |
| `scorePerNode` | \(s^{\mathrm{fp}}=\operatorname{rnd}(100\cdot\operatorname{Score})\in\{0,\ldots,10000\}\) |
| `fallbackMode` | `fresh` \| `stale` \| `dead` \| `empty` \| `all_invalid` \| `opt_out` |
| `dataStale` | SM-STALE / SM-DEAD / SM-EMPTY / all_invalid |
| `zonesMissing` / `invalidZones` | NM-UNKNOWN / NM-INVALID |
| `scoringMode`, `optInDisabled`, `slaRejected`, `podUID`, `snapshotFetchedAt` | аудит |

`Score` читает только `scorePerNode[nodeName]`. Нет второго `snapshot.Load()`, нет HTTP.

Порядок PreScore: parse labels/annotations → opt-in → \(\hat T\) / G-20 → hard SLA (2.13) → один `Snapshot()` → classify → G-08 или (2.19)/(2.23) с G-09/G-10 → `Write`.
