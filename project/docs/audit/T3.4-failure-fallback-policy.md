## Результат

Зафиксирована гарантированная деградация без прерывания scheduling cycle:

1. Матрица сбоев FF-EM … FF-CRASH (Electricity Maps, CDS, stale/dead cache, NaN/negative/future \(CI\), нет зоны, resource exhaustion).
2. Автомат SM-EMPTY / SM-FRESH / SM-STALE / SM-DEAD + поузловые NM-*.
3. `Score` во всех углеродных отказах → `fwk.NewStatus(fwk.Success)` (G-08 пишет 50, не Skip/Error).
4. Anti-Thrashing размещения: AT-01…AT-10; стратегия B сохраняет концентрацию как свойство baseline.

## Правила Fallback для T5.2 / T5.3 (сводка)

См. также `failure_and_fallback_policy.md` §7 и §15.

1. Fresh → полный (2.19) или (2.23).
2. Stale-in-window → тот же Score + Warning + метрика; **нет** множителя.
3. Dead/empty/all-invalid → Score 50 всем, Success (G-08); не \(S_C=0\).
4. Unknown/invalid zone → \(S_C=1/2\), Success (G-09/G-10).
5. `Score` никогда не возвращает Error/Unschedulable/Wait/Skip.
6. CDS/Worker: last-good, all-or-nothing, ошибка тика не затирает snapshot.
7. Anti-concentration: \(S_R\) + assume + Filter; не descheduler.
