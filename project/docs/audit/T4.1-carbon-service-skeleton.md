## Пакеты vs ARCH-14

Задание T4.1 фиксирует дерево `pkg/carbon/{config,provider,cache,api}`. Это **отдельные** Go-пакеты, не пакет формул `pkg/carbon`. Чистые функции (2.7)–(2.11) Stage 5 должен класть в `pkg/carbon/*.go`, не в эти подпакеты (`CONF-05`). При конфликте с каноном `pkg/provider` / `pkg/replay` решение за L1.

## Эстафета T4.2 — реализация провайдеров

Агенту T4.2: реализовать `v1alpha1.CarbonProvider` в `pkg/carbon/provider` (не меняя REST-пути и DTO).

1. **`MockProvider`** — синтетические `CarbonRecord` / forecast для unit/integration; без сети.
2. **`HistoricalDatasetProvider`** — чтение локального датасета (`replayDatasetPath`), схема T1.1; единица `gCO2e/kWh`, `emissionFactorType=lifecycle`.
3. **`ElectricityMapsProvider`** — HTTPS только demo (`SCOPE-EDGE-06`); ключ из `CARBON_LIVE_API_KEY`; таймаут из конфига (`GO-09`); не импортировать `pkg/scheduler`.
4. Не подставлять future actual (perfect foresight запрещён). Пустой forecast → `[]` или `ErrEmptyForecast`, не ошибка CDS.
5. `at` — часы вызывающего `Clock`, не `time.Now()` внутри адаптера.
6. После адаптеров — отдельная задача кэша/replay: валидация G-10, all-or-nothing `Store`, Replay Engine (`t_model`).
