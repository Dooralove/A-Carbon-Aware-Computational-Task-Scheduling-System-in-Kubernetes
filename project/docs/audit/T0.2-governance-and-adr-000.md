## Зафиксировано

- 18 обязательных артефактов (`SCOPE-IN-01..18`), 22 строгих запрета (`SCOPE-OUT-01..22`), 7 разрешённых пограничных случаев (`SCOPE-EDGE-01..07`).
- Четыре чеклиста DoD: код (13 пунктов), тесты (10), документация (11), эксперименты (12) + сводная таблица приёмки.
- Code style: Go `GO-01..20`, Python `PY-01..14`, конфигурации `CFG-01..08`.
- Версионирование: `VER-01..20` (SemVer, Conventional Commits, версии SSOT-документов, неизменяемость `accepted` ADR).
- Режим SSOT: уровни L0–L3, `SSOT-01..07`, процедура SSOT Change Request, правила конфликтов `CONF-01..10`.
- Воспроизводимость: `REPRO-01..20`.

## Решения, принятые сверх входных данных

| Решение | Причина |
| --- | --- |
| Схема имён ADR изменена с `NNNN-kebab` (T0.1) на `NNN_snake_case` | Коллизия с требуемым именем `000_project_scope_and_governance.md`; две схемы в одном каталоге недопустимы |
| Python зафиксирован как 3.11 + `ruff` | В инженерной спецификации версия и инструментарий не заданы |
| Пороги покрытия 85 % / 70 % | В спецификации отсутствовали; 85 % отнесены к пакетам математической модели |
| N ≥ 5 (N ≥ 10 для ключевых сценариев) | Спецификация требует «N repetitions» без числа |

## Проверка (acceptance)

- Список ограничений исчерпывающий: перекрыты все запреты из §99 и §131 инженерной спецификации, плюс явно затребованные (live migration, cross-cluster federation, carbon-aware HPA, ML-прогноз нейросетями, внешние БД / Kafka).
- Двусмысленность Scope закрыта правилом `SCOPE-EDGE-01`: неоднозначность трактуется в пользу Out-of-Scope.
- Для каждого типа артефакта определён формальный критерий приёмки и указан приёмщик (§2.5).
- Статус SSOT-документов как неизменяемых для агентов младших уровней зафиксирован в `SSOT-01` и продублирован в `docs/ssot/README.md`.
