# Аудит T4.3 — кэш CDS и REST API

- **Дата:** 2026-09-04
- **Роль:** Senior Go Systems Developer
- **Задача:** потокобезопасный in-memory кэш, фоновый sync, HTTP REST Carbon Data Service
- **Результат:** CDS отвечает по канону OpenAPI из кэша; эстафета — T4.4 (тестирование)

## Что сделано

| Артефакт | Назначение |
| --- | --- |
| `pkg/carbon/cache/cache.go` | `atomic.Pointer[CarbonSnapshot]`, `Get` / `State` / `Store(nil)` игнор (FF-INV-12), freshness на чтении |
| `pkg/carbon/cache/memory_cache.go` | `Refresh` all-or-nothing, G-10 / FF-FUT, `Loop` на `time.Ticker` |
| `pkg/carbon/cache/metrics.go` | Prometheus text: `carbon_aware_cds_*` (metrics.md §3) |
| `pkg/carbon/api/handlers.go` | `GET /api/v1/healthz` (= `/health`), `/zones`, `/zones/{zone}/current`, `/forecast`, `/metrics` |
| `cmd/carbon-service/main.go` | провайдер + часы адаптера, синхронный первый `Refresh`, затем `Loop` + `Serve` |

GET **не** вызывает провайдер и **не** двигает replay-часы. Снимок immutable: freshness/quality считаются на копии.

## Контракт HTTP

| Путь | Пустой кэш | Есть снимок |
| --- | --- | --- |
| `/api/v1/healthz` | 503 `HealthStatus` `unavailable` | 200 `ok` / `degraded` (`ready=true` на last-good) |
| `/api/v1/zones` | 503 `Status` | 200 `ZoneProfileList` |
| `/api/v1/zones/{zone}/current` | 503 | 200 + `X-Carbon-*`; неизвестная зона 404; DNS-1123 400 |
| `/api/v1/zones/{zone}/forecast` | 503 | 200, в т.ч. `forecast: []` / `forecastMode: none`; `duration` без суффикса или > 86400s → 400 |

Stale last-good после ошибки провайдера → **200** `quality: stale`, не 5xx.

## Бенчмарк кэша

Команда (без `-race`, см. ниже):

```text
go test -bench=. -benchmem -count=1 carbon-aware-k8s/pkg/carbon/cache
```

Хост: Windows amd64, AMD Ryzen 5 5600H.

| Benchmark | ns/op | B/op | allocs/op |
| --- | ---: | ---: | ---: |
| `BenchmarkCacheGet-12` | 155.4 | 321 | 2 |
| `BenchmarkCacheGetParallel-12` | 152.4 | 321 | 2 |

Чтение из кэша ≈ **0.16 µs**, требование **< 2 ms** выполняется с запасом (~10⁴).

```text
go test -bench=. -race -count=1 carbon-aware-k8s/pkg/carbon/cache
```

На этой машине **не запускается**: `-race requires cgo`, компилятора `gcc` нет (как в T4.2). Код GET — только `atomic.Load` + копия записи; concurrent-тест `TestGetConcurrentWithStore` (Get∥Refresh) **PASS** без `-race`. Прогон `-race` — Linux CI / MinGW.

## Соответствие SSOT

- Снимок all-or-nothing; невалидный \(CI\) / timestamp из будущего не публикуются; пустой тик не затирает last-good.
- Часы кэша = часы провайдера (`provider.ClockOf`), иначе replay `FetchedAt` даёт ложный age.
- Без chi (нет нового модуля / ADR). `net/http` ServeMux Go 1.22.
- Нет endpoint Score.

## Эстафета T4.4 — тестирование CDS

1. Прогон `go test -race` на Linux CI по `./pkg/carbon/cache/...` и `./pkg/carbon/api/...`.
2. Интеграция с replay-фикстурой T1.1 (`synthetic_multizone_volatile_2h_v1.json`): ступенька north 85→420, GET не двигает \(t_{\mathrm{model}}\).
3. Сверка тел с OpenAPI `api/v1alpha1/openapi.yaml` (обязательные поля, `apiVersion`/`kind`, пустой `forecast: []`).
4. Отказ провайдера после успешного тика: HTTP 200 stale, health `degraded`, Worker не должен видеть 5xx.
5. Нагрузка GET `/current` (p99 ≪ 2 ms) и проверка, что handler не ходит в сеть.
