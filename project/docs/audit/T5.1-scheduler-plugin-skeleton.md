## Что сознательно не сделано (граница T5.1)

- Автомат PreScore (opt-in, SLA/G-20, snapshot.Load, G-08/G-09/G-10, (2.19)/(2.23)) — **T5.2**.
- HTTP Cache Sync Worker к CDS — **T5.3**.
- Пакеты `pkg/energy`, `pkg/carbon`, `pkg/runtime` — не создавались.
- `SignPlugin` не реализован: opportunistic batching для профиля с CarbonAware будет выключен (допустимо для воспроизводимости стенда).
- Профили YAML B/C и Deployment — не этот таск.

Текущая заглушка PreScore пишет всем узлам `Score_neutral` (fixed-point 5000) и `fallbackMode=empty`. Это **не** финальный G-08 и не opt-out.

## Передача T5.2

Вход: этот скелет + [`01_architecture_ssot.md`](../ssot/01_architecture_ssot.md) §6.4 + [`failure_and_fallback_policy.md`](../ssot/failure_and_fallback_policy.md) §7 целиком и §15.1 + [`03_api_contracts_ssot.md`](../ssot/03_api_contracts_ssot.md) §6.

Обязанности T5.2:

1. Заменить тело `PreScore` порядком ARCH §6.4: labels/annotations → opt-in (`ARCH-16`) → горизонт/G-20 → hard SLA (`ARCH-10`) → один `snapshot.Load()` (`ARCH-06`) → G-08 / расчёт (2.19) или (2.23).
2. `Score` оставить O(1) lookup `CycleState`; при любом углеродном отказе — `Success` (nil), не `Error` (`FF-INV-08`).
3. `NormalizeScore` уже делает (2.21) `s_fp/100` + clamp `[0,100]`; не переносить min-max \(S_C\) сюда.
4. Не добавлять `Filter`/`Permit`/`QueueSort`/`Reserve`.
5. Не вызывать CDS/HTTP из горячего пути. Worker HTTP не открывать (это T5.3); читать только `atomic.Pointer` снимка.
6. Для `fwk.StateData` использовать существующую обёртку `cycleStateData` в `pkg/scheduler` — `api/v1alpha1.CarbonCycleState.Clone()` не удовлетворяет сигнатуре фреймворка.
7. Чистые формулы — в `pkg/energy` / `pkg/carbon` / `pkg/runtime`, не в `cmd/`.
8. Тесты `DOD-TEST-07` / матрица Fallback §12 политики отказов.

Контракты, которые нельзя переоткрывать: HTTP в `Score`, углеродный `Filter`, `Score=0` как нейтраль, смешение opt-out с `fallback_total`.
